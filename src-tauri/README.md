# Cappycat native core (`src-tauri`)

Rust / Tauri v2 shell for the Cappycat local AI video editor. It owns media
I/O, the local media server, the keyframe & speed-curve engine, the Python
pipeline runner and the exporter (a CPU compositor that reproduces the WebGL
preview frame by frame). The React UI lives in `../src`, the Python pipeline
in `../pipeline`.

The phase-1 exporter (`*_legacy` presets) has been **removed**: it ignored the
universal adjust, used the old /100 slider scale, and wrote straight to the
output path. The frontend never used it; asking for a `_legacy` preset now
fails with a clear error.

## Building

```bash
export PATH="$USERPROFILE/.cargo/bin:$PATH"   # Git Bash
cd src-tauri
cargo build                 # native core only (frontend not required)
cargo test --workspace      # keyframes crate + app tests
cargo clippy --workspace --all-targets
cargo build --release --bin cappycat-cli
```

`cargo tauri dev` additionally needs the frontend dev server (`npm run dev`
at http://localhost:1420, run by `beforeDevCommand`).

Tests that need ffmpeg synthesise clips in the cache dir and skip gracefully
(with `SKIP:` on stderr) when no ffmpeg is found. Tests that spawn a process
need `python` on PATH.

Slow, benchmark and diagnostic tests are `#[ignore]`d. Run them in release
(the per-pixel code is several times slower in debug; building release *test*
binaries does not touch `target/release/cappycat.exe`):

```bash
cargo test --release --lib -- --ignored --nocapture                              # all of them
cargo test --release --lib -- --ignored --nocapture export_v2_acceptance         # the exporter brief's acceptance export
cargo test --release --lib -- --ignored --nocapture export_v2_perf_1080p         # 1080p24 full-grade throughput
cargo test --release --lib -- --ignored --nocapture export_real_clips_range      # <clips folder>/clip1 + clip2, 10 s range
cargo test --release --lib -- --ignored --nocapture bench_                       # per-stage micro-benchmarks
cargo test --release --lib -- --ignored --nocapture diag_real_frame              # baked grade on a real frame
cargo test --release --lib -- --nocapture baked_grade_matches_exact_grade        # bake accuracy report
```

## ffmpeg: binaries instead of libav (deviation)

The design spec lists `ffmpeg-next`. This machine has no libav development
libraries, only the WinGet Gyan build of `ffmpeg.exe`/`ffprobe.exe`, so
**phase 1 shells out to the binaries** (`src/ffmpeg.rs`). Discovery order:

1. `CAPPYCAT_FFMPEG_DIR` (directory containing both executables)
2. `PATH`
3. `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg*\ffmpeg-*\bin\`
4. `%LOCALAPPDATA%\Microsoft\WinGet\Links\`

All ffmpeg use goes through that module (the exporter's decoders/encoder use
`ffmpeg::command`) so an in-process decoder can replace it later. Every ffprobe
run has a 30 s timeout, short ffmpeg jobs (frames, thumbnails) 120 s,
`python -m cappycat_pipeline order` 60 s.

**Probing.** `probe` reports the *displayed* size: a stream with a 90° / 270°
display matrix (`side_data_list[].rotation`) or legacy `rotate` tag — portrait
phone clips — gets its width and height swapped, matching ffmpeg's auto-rotated
frames. The exporter re-probes every source once while planning (in
parallel), so projects saved with the coded size still export upright.

**Colour.** Decoders convert YUV → RGB with the source's `color_space` tag, and
untagged video with **BT.709 at ≥ 720 lines, BT.601 below** (what browsers do;
the output is tagged BT.709), limited range unless tagged full / `yuvj*`, using
swscale's exact path (`accurate_rnd+full_chroma_int`; the default fast path is
up to 2 levels off). Still images use their tags or BT.601.

## Child processes

* Every child (ffmpeg, ffprobe, python) starts without a console window and is
  assigned to one process-wide **Windows Job Object** with
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. The handle is never closed by the app,
  so when Cappycat exits — normally, by a crash or killed — the OS closes it and
  every remaining child dies, including python's own ffmpeg children (they
  inherit the job).
* Python children (`analyze`, `separate`, `interpolate`, `order`) run with
  `CAPPYCAT_WATCH_STDIN=1` (+ `PYTHONUNBUFFERED=1`, `PYTHONIOENCODING=utf-8`)
  and a piped stdin that Rust holds open. To stop one, Rust closes stdin (the
  pipeline's watchdog kills its own children and exits), waits up to 2 s, then
  kills its whole process tree (a nested per-child job).
* On `RunEvent::ExitRequested` every job is cancelled (up to 3 s are given for
  exports to delete their partial files and python to exit).
* Cancelling never blocks the UI thread: waits poll `try_wait` without holding
  the child's lock, and python stops run on a background thread.

## One GPU job at a time

Analysis (`run_pipeline`), `separate_audio` and the optical-flow `interpolate`
runs of exports share a FIFO queue (`JobManager::gpu`). A job that has to wait
emits its normal progress event with `pct: 0` and the message
**`waiting for the GPU (another AI job is running)`** (first ~150 ms after the
command returned the job id, then every 2 s until it starts) —
`pipeline://progress { jobId, event:"progress", stage:"ingest", clip:null, pct:0, message }`,
`separate://progress { jobId, pct:0, clipPct:0, message, clip:null }`,
`export://progress { jobId, pct:0, message }` — and starts when every job
queued before it has finished. Cancelling a queued job removes it from the
queue; it then ends with its normal cancelled event (`pipeline://exit
{cancelled:true}`, `separate://done {ok:false, error:"cancelled"}`,
`export://done {ok:false, error:"cancelled"}`). A queued job counts as running
for `cancel_*`.

## Logs

Rolling daily log files in `%LOCALAPPDATA%\Cappycat\logs\` (`<CAPPYCAT_HOME>\logs`)
(`cappycat.YYYY-MM-DD.log` for the app, `cappycat-cli.YYYY-MM-DD.log` for the
CLI, 14 files kept), `info` and up (`CAPPYCAT_LOG=debug` for more). Panics are
logged. `app_paths().logsDir` returns the folder. `cappycat-cli … -v` prints
the export's info lines (stages, bake report, timings) on the console.

## Cache

`%LOCALAPPDATA%\Cappycat\cache\` (`CAPPYCAT_CACHE_DIR`, `<CAPPYCAT_HOME>\cache`)
* `thumbs\<sha1>\<n>.jpg` — thumbnail strips (key = sha1 of path|size|mtime|count|width); written to
  `<sha1>.tmp-<uuid>\` and renamed into place when complete
* `analysis\<jobId>.json` — pipeline output
* `flow\<sha1>.mp4` — optical-flow intermediates (key = sha1 of path|mtime|inMs|outMs|fps:F — or the factor of a `--factor` run)
* `export\<jobId>\` — per-export scratch (audio mix WAVs), removed when the job ends
* `stems\<sha1>\{vocals,background}.wav` + `meta.json` — voice separation stems, written by the
  Python `separate` command (key = sha1 of path|size|mtime|model)
* `test\` — synthetic fixtures written by the tests

## Media server

Started in `setup`, bound to `127.0.0.1:0`. **Security model** (any web page
could otherwise read local files through it):

* Every route lives under a random per-launch secret: the base URL is
  **`http://127.0.0.1:<port>/t/<token>`** (32 hex chars). `invoke("media_server_url")`
  and `app_paths().mediaServerUrl` return it; the frontend keeps appending
  `/media?path=…` etc. Anything outside `/t/<token>/` is `404`.
* The `Host` header must be exactly `127.0.0.1:<port>` (DNS-rebinding guard) → else `403`.
* CORS is granted only to `tauri://localhost`, `http://tauri.localhost`,
  `https://tauri.localhost` and `http://localhost:1420` (dev).
* **Only registered files are served** (`403` otherwise). Paths are compared
  canonicalised and case-insensitively (Windows). Registered automatically:
  results of `probe_media`, `import_media`, `scan_clips_folder`; every asset,
  LUT and stem path of `load_project` / `open_document` (projects and
  analyses); every clip / asset / timeline path of a `pipeline://analysis`
  payload; the stems of every `separate://result`; the output of every
  successful export. Anything else: `invoke("register_media", { paths })`.
* UNC / device / verbatim paths (`\\host\share\…`, `\\?\…`, `//…`) and `..` are
  rejected with `400` before touching the file system (mapped drive letters work).

| route (below `/t/<token>`) | notes |
|---|---|
| `GET /media?path=<abs>` | HTTP Range streaming (200 / 206 / 416, `Accept-Ranges`, `Content-Range`, MIME by extension). `ETag` + `Last-Modified` + `Cache-Control: no-cache` (a re-exported file is never served stale), `304` on a matching `If-None-Match`, `If-Range` honoured. A malformed `Range` is ignored (`200`), a well-formed unsatisfiable one is `416`. `HEAD` works. Use `encodeURIComponent` (spaces / unicode work). |
| `GET /frame?path=<abs>&ms=<n>&w=<n>` | one JPEG frame (`w` default 640, 16..4096); at most 3 ffmpeg at a time, 64-entry LRU cache (keyed by path + size + mtime + ms + w), ffmpeg killed when the client disconnects or after 30 s |
| `GET /thumb/<sha1>/<n>.jpg` | cached thumbnail (URLs come from `extract_thumbnails`) |
| `GET /health` | `ok` |

Argument names are camelCase in JS; errors are `string`. **All commands are
async** (Tauri runs synchronous commands on the main thread); `media_server_url`,
`app_paths`, `cancel_*`, `evaluate_keyframes` and `speed_curve_lut` changed from
sync to async without any change on the JS side (`invoke` always returns a promise).

Model: `Clip.linkId?: string` (skipped when absent) — the same id on a video
clip and its mirrored audio clip; round-trips through save / load / export
(the exporter's audio de-duplication does not need it).
`effective_grade` only touches — and clamps — the fields the universal preset
has a delta for (like `effectiveGrade` in grade.ts).

Voice separation: `ClipAudio.voice` (`original` \| `voice` \| `background`, default `original`,
always serialised; unknown values load as `original`) and `Asset.stems?: { vocals, background }`
(omitted when absent).

Model additions mirrored from the pipeline: `Asset.orderReason?`,
`PipelineOptions.keepOrder` (default false), `Shot.cast?: string[]`,
`DuplicateFinding.character?`, `DuplicateFinding.characterName?` (all omitted
from JSON when absent). A prompt starting with `-` is passed to argparse with a
leading space so it is not read as an option.

### Clips folder (`scan_clips_folder`, `app_paths().clipsDir`)

Default folder when no `path` is given (repo = parent of the pipeline dir):
1. `<repo>/clips` if it holds at least one video file;
2. else the most recently modified direct child of the repo whose name
   contains `clip` (case-insensitive, e.g. `cappycat- clips`) and holds video
   files — `node_modules`, `target`, `dist`, `pipeline`, `src`, `src-tauri`,
   `.git` are ignored;
3. else `<repo>/clips`, created by `scan_clips_folder`.

The pipeline dir is `CAPPYCAT_PIPELINE_DIR`, else `<repo>/pipeline` of a checkout found from the
cwd or the exe, else the bundled `<exe dir>/pipeline` of an installed app (see *Locations*
below; canonicalised with `dunce`, so no verbatim prefix). Installed, the default clips folder is
`Documents\Cappycat\Clips`.

The order comes from `python -m cappycat_pipeline order <folder> --json`
(`{ folder, files: [{ path, name, order, reason, key }], warnings }`, cwd =
pipeline dir, venv python preferred, 60 s timeout). If Python fails the files
are sorted naturally by name in Rust (`orderReason` = `natural filename sort
(pipeline unavailable)` plus a `pipeline unavailable - using natural filename
sort` warning). Only video / audio / image / `.cube` files are returned; files
that fail to probe become warnings.

## Export (v2: frame compositor)

The export is rendered frame by frame on the CPU with the preview's maths
(`src/engine/color/shaders.ts`, `renderer.ts`, `src/engine/playback.ts`), so it
looks like the preview.

**Output file.** The encoder writes `<dir>/<name>.partial-<jobId>.<ext>` next
to the target; on success the file is renamed over the target (retried for
2 s if a player holds the old file; if that still fails the error names the
kept partial file). A failed or cancelled export deletes only its partial file —
an earlier export at the target is never lost. An output path equal
(canonicalised, case-insensitive) to any asset, LUT or stem path of the project
is refused.

**Validation** (`Project::validate`, before anything is sized from the
document): `width`/`height` 16..8192, `fps` in (1, 240], finite clip times and
speed points, a timeline of at most 4 h, ≤ 256 tracks and ≤ 50 000 clips. Every
video / image source of a visible clip and every audio source of an audible
clip in the range must exist; a LUT that cannot be read fails the plan. Job
threads run under `catch_unwind` (release builds use `panic = "unwind"`), so an
internal error fails the job (`export://done { ok:false, error:"internal error: …" }`)
instead of taking the app down.

1. **Plan** (synchronous, so bad projects fail in `invoke`): duration = end of
   the last clip on any track; output frame `n` is at `start + n / fps`.
   Every clip on a non-muted video track (a muted track is hidden; later
   tracks draw on top) is resolved per covered frame with the `resolveClip`
   port: keyframes-crate speed LUT, freeze frame, reverse, transform and
   mask-rect keyframes (outgoing easing), reframe crop interpolation. A speed
   curve with no points plays at 1× like the preview. Each source is probed
   once, in parallel (displayed size, average fps, colour tags). Each distinct
   effective grade is baked (below).
2. **Optical flow**: clips with `speed.opticalFlow` whose curve dips below 1×
   run `python -m cappycat_pipeline interpolate <src> --in-ms A --out-ms B
   --factor N --out <cache>` once (N = ceil(1/minSpeed) ≤ 8, cached under
   `cache\flow`) — through the GPU queue; the intermediate replaces the source
   for that clip. If Python or the subcommand fails, a `warn` is logged and the
   clip uses neighbour-frame blending on the refined slow-motion grid (real
   in-between frames of high-fps footage); a missing interpreter/subcommand is
   not retried for the other clips of the same export.
3. **Audio**: every audible clip — audio tracks, plus video-track clips not
   mirrored by an audio-track clip with the same `assetId`/`startMs`; muted
   tracks and clips skipped — decodes only the part of its source the export
   range needs (streamed straight to f32) and is resampled along the same time
   map (linear interpolation, i.e. varispeed: pitch follows speed; silence
   during freeze holds; reversed clips play backwards), `gainDb` applied and
   mixed in 10 s blocks streamed into a float WAV (RF64 past 4 GB, i.e. > 3.1 h).
   A source that cannot be decoded fails the export. A clip whose
   `audio.voice` is `voice` / `background` decodes the asset's `stems.vocals` /
   `stems.background` WAV instead (same range and time map); missing stems →
   `warn` + original audio. If any clip has `audio.normalize` the mix goes
   through a two-pass `loudnorm=I=-14:TP=-1.5:LRA=11` (linear).
4. **Video**: per clip a producer thread runs its own ffmpeg decoder (`-ss`
   before `-i`, `fps=<grid>:start_time=0`, downscaled when the project never
   shows the source above 1:1 — but always full size when the clip is
   sharpened, since the preview's sharpening reads the source's own texels —,
   the source's colour matrix, `rawvideo rgb24`), keeps a small ring (forward)
   or decodes reversed clips in memory chunks (≤ 1.2 GB / 600 frames),
   cross-fades two neighbour frames when playing slower than 1× without a flow
   intermediate, applies the separable form of the shader's 7×7 gaussian blur
   and builds the sharpen detail layer; frames flow through bounded channels.
   Frame, float and output buffers are recycled through per-layer pools and
   the encoder's return channel; a frame that needs no blend / blur is
   sampled as 8-bit directly (no float copy). The compositor grades each pixel
   in shader order (exposure, brightness, contrast, highlights/shadows,
   brilliance, sharpness, temperature/tint, lift/gamma/gain/offset,
   saturation/vibrance, 8-channel HSL, RGB curves, 3D LUT × intensity,
   vignette, grain), applies mask and opacity and blends onto an opaque black
   canvas (`normal` = premultiplied `ONE, ONE_MINUS_SRC_ALPHA`; `multiply`,
   `screen`, `overlay`, `softLight`, `darken`, `lighten`, `colorDodge` = W3C
   formulas). A writer thread streams `rgb24` to the encoder (BT.709 matrix,
   tagged): `libx264 -crf 18 -preset medium`, `h264_nvenc -cq 19 -preset p5`,
   `prores_ks -profile:v 3`; audio AAC 192k (PCM for ProRes). Frame rates are
   passed exactly (`23.976` → `24000/1001`).

**NVENC fallback.** `h264_nvenc_mp4` is re-rendered with libx264 only when the
encoder error comes from NVENC itself (`nvenc`, `cuda`, `No capable devices`,
`OpenEncodeSession…`); after that, later exports in the same session go
straight to libx264. Missing files, a full disk etc. fail once.

**Baked grade** (`render/bake.rs`). The per-pixel, position-independent part of
each clip's *effective* grade (clip grade + universal adjust) is sampled at
plan time into two tetrahedral lattices — `pre` (exposure … brilliance) over
the source cube and `tone` (white balance, wheels, gamma, saturation, HSL)
over the range `pre` (+ the sharpening term) can reach — and the compositor does
two lookups per pixel instead of the stage chain. Sharpening, blur, mask,
vignette, grain and the table stages (curves, LUT) stay exact per pixel. The
`tone` lattice's node offsets put the `max(c,0)` planes on cell faces and the
HSL hue-sector planes on tetrahedron faces; every cell is checked against the
exact grade at 64 interior points and cells over 0.6/255 (clamps, dark /
near-grey HSL regions) are graded exactly. 33³ is used when ≤ 4 % of its cells
need that, else 65³; a `tone` lattice with more than 25 % exact cells is
dropped (only `pre` is baked). The end-to-end error is measured on 40 k probe
colours and a bake over 0.8/255 is rebuilt with a tighter tolerance or dropped
(exact grading). `baked_grade_matches_exact_grade` checks a dense 49³ grid (with
and without a detail term) for the default universal preset, the preset without
sharpening and six random grades: max error 0.13–0.80/255 (preset: 0.8/255),
mean ≤ 0.05/255. The universal preset bakes in ~170–190 ms (65³, 15.8 % exact
cells). Measured effect: on a real 720p frame the exact cells still hold ~45 %
of the pixels (dark / near-grey colours under the preset's HSL), so a lookup is
not dramatically cheaper than the (already table-driven) exact grade — the
composite of that frame goes from 10.9–11.1 ms to 10.3–11.0 ms
(`diag_real_frame`), the export's composite from 12.0 to 10.8 ms/frame and its
video stage from 66 to 71 fps. `CAPPYCAT_NO_BAKE=1` disables baking (A/B
timing).
Grades without expensive stages (HSL, brilliance, exposure roll-off, gamma) are
not baked (a few multiply-adds are cheaper than two lattice lookups). The export log reports every bake (size,
exact-cell share, probe error, time: ~180 ms for the universal preset).

**Variable frame rate.** Frame indices never come from the container's
nominal rate: every decoder resamples by timestamp onto a uniform grid
(`fps=<project fps>`; for slow motion from high-fps footage the grid is
refined by `min(ceil(1/minSpeed), round(avgFps / projectFps))`; flow
intermediates are decoded at their own rate). Phone clips with
`r_frame_rate=60` and ~24 fps average map correctly — see
`vfr_source_maps_by_timestamp` and `export_real_clips_range`.

**Known deviations from the preview** (each < 1/255 unless noted): the baked
grade (≤ 1/255, see above); identity RGB curves are skipped (the preview
samples an 8-bit identity texture); non-identity curves use a fused
4096-entry table per channel; the HSL channel weights come from a 4096-entry
hue table (< 2e-5); LUTs stay f32 (the preview uploads RGB8),
`DOMAIN_MIN/MAX` ignored as in the preview; grain uses the shader's hash in
CPU f32 (same distribution, different pattern than a GPU); the blur is the
separable equivalent of the 7×7 kernel (differs only at image edges); the
source frame is the one nearest to the grid tick (the `<video>` element shows
the last frame with pts ≤ t, so up to half a source frame apart); output
durations integrate the speed curve with the keyframes crate (Simpson, 1024
cells) instead of speed.ts (trapezoid, 256 — sub-millisecond apart); stacked
video tracks and blend modes go beyond the preview, which only draws the top
clip.

**Not handled yet** (documented, not fixed):
* Still images: EXIF orientation is honoured only when ffmpeg reports it as a
  display matrix (probe + auto-rotate); animated GIFs export their first frame
  as a still; HDR (PQ / HLG) sources are not tone-mapped (the preview and the
  export can differ).
* Network paths: the media server does not serve UNC paths (`\\host\share`);
  use a mapped drive letter.

## Feature set v2 (`docs/FEATURES_V2.md`)

### Model additions (`model.rs`, all optional, omitted from JSON when absent)

`Project.frameInterpolation` (`none` | `frameBlend` | `opticalFlow`, default `opticalFlow`),
`Asset.stemOf { assetId, stem: 'vocals' | 'background' }`, `Track.role` (`voice` | `background`),
`ClipAudio.keepPitch` (default `true`), `ClipAudio.fadeInMs` / `fadeOutMs`, `ClipAudio.volume`
(`Keyframed<number>`, dB), `Clip.transitionIn { type, durationMs (default 500) } | null`,
`Clip.effect { type, intensity (default 1), params? }`, `Clip.fadeInMs` / `fadeOutMs`.
`TransitionType` / `EffectType` (the 16 + 16 camelCase names), `FrameInterpolation`,
`TrackRole` and `StemKind` never fail to load: an unknown name becomes `Other(name)` (logged at
`warn`) and is written back verbatim; transitions render it as `dissolve`, effects skip it,
`frameInterpolation` behaves as `opticalFlow`. `Project::link_groups()` lists link groups of any
size. **Validation** now also requires `fps` ∈ {24, 25, 30, 40, 48, 50, 60, 23.976, 29.97} (±0.01)
and finite, non-negative fades / transition lengths / effect params / volume keyframes (out-of-range
finite values are clamped when rendering).

### Frame rate and interpolation (`export/mod.rs` `frame_supply`, `export/flow.rs`)

A clip needs frames it does not have when `project fps > 1.1 × source avg fps × slowest speed`
(over the frames the export renders). Then:
* `none` → the nearest source frame is repeated;
* `frameBlend` → the source is decoded on its own frame grid and neighbouring source frames are
  cross-faded (weight = the fractional position);
* `opticalFlow` (default) → `python -m cappycat_pipeline interpolate <src> --in-ms A --out-ms B
  --target-fps F --out <mp4>` with `F = ⌈project fps / slowest speed⌉` (≤ 8 × source fps, ≤ 480) over
  just the source range the export shows (± 2 frames), through the GPU queue, cached under
  `cache\flow\<sha1(path|mtime|A|B|fps:F)>.mp4`; frame `k` of the intermediate is source time
  `A + k/F`. Failure → `frameBlend` with a `warn`; a pipeline without `--target-fps` is retried with
  `--factor ⌈F / source fps⌉`. A clip whose `speed.opticalFlow` is `false` opts out (frame blending).
Otherwise (the output needs no more frames) the pre-v2 path is unchanged. Each such clip logs one
line (`clip …: 24.00 fps source at 1.50× = 36.0 fps effective, 60 fps output (opticalFlow): optical
flow at 40 fps …`).

### Audio (`export/stretch.rs`, `export/audio.rs`)

* Speed ≠ 1 and `keepPitch` (default): pitch-preserving **WSOLA** following the speed map sample
  by sample (ramps native, 0.1×–10×): 25 ms Hann frames at 50 % overlap, ±10 ms similarity search
  (normalised cross-correlation, coarse-to-fine). Freeze holds stay silent, reversed clips play
  backwards. `keepPitch: false` = varispeed, with a Blackman-windowed sinc low-pass
  (cutoff `0.92 × 0.5 / speed`) above 1×.
* Gain `dbToLin(gainDb + volume(t)) × fadeIn(t) × fadeOut(t)`: equal-power (sine) fades clamped to
  half the clip, `volume` = keyframed dB (keyframes crate, outgoing easing), evaluated every 16
  samples.
* Stem clips (audio assets with `stemOf`) are ordinary audio clips: the mirrored-audio rule only
  ever drops *video-track* clips, and a stem clip plays its own file (its `voice` mode is ignored).
* `cameraSnap` adds `procedural_shutter(48000)` at −6 dB × intensity at the effect start.

### Transitions, effects, video fades (`render/transitions.rs`, `render/fx.rs`)

A 1:1 port of the preview's GLSL (`src/engine/color/fxShaders.ts`) and `effectFrame`
(`src/engine/effects.ts`); every formula and constant is in the module docs of the two files
(display-value mixing, black outside the frame, house blur kernel in output px, PCG noise with
`pcg(0) = 129708002`, `pcg(1) = 2831084092`, mulberry32 shutter). Parity tests
(`parity_with_the_preview_formulas` in both files) check rendered pixels against values computed by
hand from those formulas.
* **Transitions**: for `transitionIn` on clip B with a clip A on the same video track ending where B
  starts (gap < 1 frame), `d = clamp(durationMs, 100, 3000)`, ≤ both clips; A is extended by `d/2`
  past its out-point and B starts `d/2` early (source handles when the file has them, else the
  first / last frame holds; speed maps continue at the boundary speed). During the window A and B
  are each composited over the lower tracks into scratch canvases and mixed with
  `p = easeInOut(raw)`.
* **Effects**: every non-muted FX track, in track order (clips by start), is applied to the
  composited frame at the output time; `t` = time since the effect clip starts, `D = outMs − inMs`.
* **cameraSnap**: while it runs the video layers (and transitions) show the timeline at the snap's
  start (`TimelinePlan::video_time`), so range exports starting inside a snap still freeze on the
  right frame; the polaroid + flash then apply to that composite.
* **Video fades**: `Clip.fadeInMs / fadeOutMs` multiply the layer colour by
  `min(1, t/fadeIn)·min(1, (L − t)/fadeOut)` before opacity (per-layer `Layer::fade`).

### Locations (`paths.rs`)

runs "from the repo" when the exe folder (or one of its four parents) is a checkout root — it has

`pipeline/` next to it is *installed* whatever the working directory is; otherwise the cwd and its
parent are tried. `CAPPYCAT_LAYOUT=installed` forces the installed layout. Dev mode is unchanged (same pipeline dir, presets, clips folder,
cache and logs — `%LOCALAPPDATA%\Cappycat` is the same folder as the old `%LOCALAPPDATA%\cappycat`).

| location | override | installed layout |
|---|---|---|

## Keyframe semantics

Between keyframes `a` → `b`, the *outgoing* keyframe's easing (`a.easing`,
`a.bezier`) shapes the segment; before the first / after the last keyframe the
value is held; empty `keyframes` → `static`.

Note: the keyframes crate's built-in speed presets (used only when a curve has
no points) differ from `SPEED_PRESETS` in `src/engine/speed.ts`; the UI always
stores the points, and the exporter treats a point-less curve as 1× like the
preview.
